# Kufar Support Bot

Модули: `main.py` (бот и цикл опроса), `kufar_fetch.py` (API Kufar), `filters.py` (отбор объявлений), `config.py`, `db.py`, `handlers.py`, `formatter.py`.

## Запуск

Скопируйте `.env` из примера (или создайте вручную), укажите `TOKEN`. Установите зависимости: `pip install -r requirements.txt`, затем `python main.py`.

Тесты: `python -m unittest discover -v`

Диагностика фильтров: в `.env` задайте `FILTER_DEBUG_LOG=true` — в лог пойдут причины отклонения объявлений (режим «только обмен» и обычная рассылка).

## База данных и Git

Файлы SQLite **не коммитятся** (см. `.gitignore`: `bot.db`, `data/`).

### Локально

По умолчанию база: **`data/bot.db`** в папке проекта. При первом запуске после обновления старый `bot.db` из корня проекта копируется в `data/` автоматически.

### BotHost.ru (деплой из GitHub)

При каждом push пересобирается контейнер; **`bot.db` в корне репозитория стирается**. На BotHost есть постоянная папка **`/app/data`** — она **не** перезаписывается из Git.

Бот сам кладёт базу в `/app/data/bot.db`, если эта папка есть (типично на BotHost). Дополнительно в панели бота можно задать:

```env
DB_PATH=/app/data/bot.db
```

**Один раз после обновления:** если важные данные остались в старом файле на сервере, через файловый менеджер BotHost скопируйте `bot.db` в папку **`data`** бота (путь `/app/data/bot.db`), затем перезапустите.

- Делайте **резервные копии** `/app/data` или `data/bot.db` перед крупными обновлениями.
- В продакшене — **один** процесс бота и **одна** БД.

## Средняя цена и инстансы

Средняя рыночная цена для VIP считается по таблице `market_prices` в **одной** базе. Чтобы у всех пользователей было одно и то же число для одной модели:

- в продакшене должен работать **один** процесс бота и **одна** БД по `DB_PATH`;
- несколько копий бота с разными файлами SQLite дадут разные средние.

После каждого успешного запроса к Kufar бот дополняет `market_prices` из **всего** полученного батча объявлений (с тем же «умным» фильтром, что и для VIP-режимов «все iPhone»), а не только из отправленных в Telegram сообщений.

## Тестирование при живых пользователях

- Отдельный **стейджинг**: второй токен бота (`TOKEN`) и отдельный **`DB_PATH`**, чтобы не трогать продакшен-данные.
- Изменения в **ветке**, проверка на стейдже, затем merge в основную ветку и деплой.
