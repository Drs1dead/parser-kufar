# Kufar Support Bot

Модули:

| Файл / папка | Назначение |
|--------------|------------|
| `main.py` | Запуск бота и polling Telegram |
| `poller.py` | Фоновая рассылка объявлений |
| `user_matching.py` | Сопоставление объявлений с фильтрами пользователя |
| `handlers/` | Telegram: `start`, `nav`, `goods`, `admin` — см. [ARCHITECTURE.md](ARCHITECTURE.md) |
| `kufar_fetch.py` | API Kufar |
| `filters.py` | Отбор объявлений |
| `bot_ui.py` | Тексты и клавиатуры |
| `db.py`, `config.py`, `formatter.py` | База, настройки, формат сообщений |

Цены в интерфейсе — **белорусские рубли** (обозначение **Br**, код BYN), как на Kufar.by.

## Запуск

Скопируйте `.env` из примера (или создайте вручную), укажите `TOKEN`. Установите зависимости: `pip install -r requirements.txt`, затем `python main.py`.

**Логи (продакшен):** по умолчанию тихий режим — одна строка при старте, без спама каждый цикл опроса. В `.env`:

- `LOG_LEVEL=INFO` — обычный (по умолчанию)
- `LOG_LEVEL=DEBUG` — детали опроса Kufar, кнопки, полные traceback при ошибках
- `FILTER_DEBUG_LOG=true` — почему отбрасываются объявления (только при отладке фильтров)

Тесты (необязательны на сервере): `python -m unittest discover -v` — локальная проверка фильтров и рефералки после правок кода.

## База данных и Git

Файлы SQLite **не коммитятся** (см. `.gitignore`: `bot.db`, `data/`).

### Локально

По умолчанию база: **`data/bot.db`** в папке проекта. При первом запуске после обновления старый `bot.db` из корня проекта копируется в `data/` автоматически.

### BotHost.ru (деплой из GitHub)

При каждом push пересобирается контейнер; **`bot.db` в корне репозитория стирается**. На BotHost есть постоянная папка **`/app/data`** — она **не** перезаписывается из Git.

Бот сам кладёт базу в `/app/data/bot.db`, если эта папка есть (типично на BotHost). Дополнительно в панели бота можно задать:

```env
DB_PATH=/app/data/bot.db
```

**Один раз после обновления:** если важные данные остались в старом файле на сервере, через файловый менеджер BotHost скопируйте `bot.db` в папку **`data`** бота (путь `/app/data/bot.db`), затем перезапустите.

- Делайте **резервные копии** `/app/data` или `data/bot.db` перед крупными обновлениями.
- В продакшене — **один** процесс бота и **одна** БД.

## Средняя цена и инстансы

Средняя рыночная цена для VIP считается по таблице `market_prices` в **одной** базе. Чтобы у всех пользователей было одно и то же число для одной модели:

- в продакшене должен работать **один** процесс бота и **одна** БД по `DB_PATH`;
- несколько копий бота с разными файлами SQLite дадут разные средние.

После каждого запроса к Kufar бот дополняет `market_prices` только из **целых телефонов** (без коробок, стёкол, плат и т.п.). Рассылка и VIP-потоки учитывают модели из «Товары».

**Охват листинга:** `KUFAR_SIZE` по умолчанию **40** объявлений на поисковый запрос (env). Если объявлений не хватает — можно поднять `KUFAR_SIZE` или позже добавить пагинацию по `cursor` API.

## Фильтр памяти

В меню **«Память»** выбираются объёмы: 64, 128, 256, 512 GB и **более** (от 512 GB, включая 1 ТБ).

- **Обычный аккаунт:** один объём; новый выбор заменяет прежний. По умолчанию при регистрации — **64 GB**.
- **VIP:** можно выбрать несколько объёмов; снять последний нельзя (останется минимум 64 GB). При окончании или снятии VIP память сбрасывается на **64 GB**.
- Если в объявлении Kufar память **не указана**, оно проходит под любой выбранный объём.

В БД: поле `users.memory_volumes` (CSV, например `64,128` или `512+`).

## Реферальная программа

Во вкладке **VIP** — персональная ссылка вида `https://t.me/<бот>?start=ref_<код>`.

- Пригласивший получает **+1 день VIP** за каждого **нового** пользователя, который впервые открыл бота по этой ссылке (`REFERRAL_VIP_DAYS_PER_FRIEND` в `.env`, по умолчанию 1).
- Повторный `/start` того же друга или реактивация старого аккаунта бонус **не** дают.
- Свою ссылку использовать нельзя.

Таблица `referrals` фиксирует, за кого бонус уже начислен.

## Тестирование при живых пользователях

- Отдельный **стейджинг**: второй токен бота (`TOKEN`) и отдельный **`DB_PATH`**, чтобы не трогать продакшен-данные.
- Изменения в **ветке**, проверка на стейдже, затем merge в основную ветку и деплой.
